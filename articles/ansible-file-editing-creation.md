# Ansible: Editing Files and Creating Scripts on Remote Servers

All the Ansible modules and patterns for creating new files, editing existing ones, and deploying scripts on remote hosts — from simple one-liners to full template-driven configuration management.

## Module Overview

| Module | Purpose | Idempotent | Best For |
|--------|---------|------------|----------|
| `copy` | Copy a local file to remote hosts | Yes | Static configs, scripts, certificates |
| `template` | Render a Jinja2 template to remote hosts | Yes | Dynamic configs with variables |
| `lineinfile` | Ensure a single line is present/absent | Yes | Editing one line in an existing file |
| `blockinfile` | Ensure a block of lines is present/absent | Yes | Adding multi-line sections |
| `replace` | Regex find-and-replace across a file | Yes | Pattern-based edits |
| `file` | Create files/directories, set permissions | Yes | Empty files, directories, symlinks |
| `assemble` | Combine file fragments into one file | Yes | Building configs from parts |
| `fetch` | Copy a file from remote to local | Yes | Pulling files back |

## Creating New Files

### copy — Deploy a Local File

The `copy` module transfers a file from the control node (or inline content) to managed hosts.

```yaml
- name: Deploy a script from local files/
  copy:
    src: scripts/cleanup.sh
    dest: /usr/local/bin/cleanup.sh
    owner: root
    group: root
    mode: '0755'
```

The `src` path is relative to the role's `files/` directory or the playbook directory.

#### Inline Content (No Source File Needed)

Use `content` to create a file directly from a string — no local source file required.

```yaml
- name: Create an environment file
  copy:
    content: |
      APP_ENV=production
      APP_PORT=8080
      DB_HOST=10.0.1.5
      LOG_LEVEL=warn
    dest: /etc/myapp/app.env
    owner: appuser
    group: appuser
    mode: '0600'
```

#### Create a Shell Script Inline

```yaml
- name: Create a backup script
  copy:
    content: |
      #!/bin/bash
      set -euo pipefail
      TIMESTAMP=$(date +%Y%m%d_%H%M%S)
      BACKUP_DIR="/var/backups/myapp"
      mkdir -p "$BACKUP_DIR"
      pg_dump mydb | gzip > "$BACKUP_DIR/mydb_${TIMESTAMP}.sql.gz"
      find "$BACKUP_DIR" -name "*.sql.gz" -mtime +7 -delete
    dest: /usr/local/bin/backup-db.sh
    owner: root
    group: root
    mode: '0755'
```

#### Validate Before Deploying

Use `validate` to run a command against the file before it's placed at the final destination. `%s` is replaced with the temp file path.

```yaml
- name: Deploy sudoers file (validate syntax first)
  copy:
    src: sudoers.d/deploy-user
    dest: /etc/sudoers.d/deploy-user
    owner: root
    group: root
    mode: '0440'
    validate: /usr/sbin/visudo -cf %s

- name: Deploy sshd config
  copy:
    src: sshd_config
    dest: /etc/ssh/sshd_config
    validate: /usr/sbin/sshd -t -f %s
  notify: restart sshd
```

### template — Dynamic Files with Jinja2

The `template` module renders a Jinja2 template and deploys the result. Use it whenever the file content depends on variables, facts, or logic.

```yaml
- name: Deploy nginx vhost config
  template:
    src: nginx-vhost.conf.j2
    dest: /etc/nginx/sites-available/{{ app_name }}.conf
    owner: root
    group: root
    mode: '0644'
  notify: reload nginx
```

**templates/nginx-vhost.conf.j2:**

```jinja
server {
    listen {{ nginx_port | default(80) }};
    server_name {{ server_name }};

    location / {
        proxy_pass http://{{ app_host }}:{{ app_port }};
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

{% if ssl_enabled | default(false) %}
    listen 443 ssl;
    ssl_certificate /etc/ssl/certs/{{ app_name }}.crt;
    ssl_certificate_key /etc/ssl/private/{{ app_name }}.key;
{% endif %}
}
```

#### Template with Loops

```jinja
# /etc/hosts.allow
{% for host in allowed_hosts %}
sshd: {{ host }}
{% endfor %}
```

#### Template with Facts

```jinja
# Generated by Ansible on {{ ansible_date_time.iso8601 }}
# Host: {{ ansible_hostname }} ({{ ansible_default_ipv4.address }})

[server]
hostname = {{ ansible_fqdn }}
cpus = {{ ansible_processor_vcpus }}
memory_mb = {{ ansible_memtotal_mb }}
```

#### Validate Templates Too

```yaml
- name: Deploy Apache config from template
  template:
    src: httpd.conf.j2
    dest: /etc/httpd/conf/httpd.conf
    validate: /usr/sbin/httpd -t -f %s
  notify: restart httpd
```

### file — Create Empty Files and Directories

The `file` module manages file system objects without content.

```yaml
- name: Create application directories
  file:
    path: "{{ item }}"
    state: directory
    owner: appuser
    group: appuser
    mode: '0755'
  loop:
    - /opt/myapp
    - /opt/myapp/config
    - /opt/myapp/logs
    - /opt/myapp/data

- name: Create an empty log file
  file:
    path: /var/log/myapp/app.log
    state: touch
    owner: appuser
    group: appuser
    mode: '0644'

- name: Create a symlink
  file:
    src: /opt/myapp/current/bin/myapp
    dest: /usr/local/bin/myapp
    state: link
```

> **Note:** `state: touch` updates the file's timestamp if it already exists (like the `touch` command). Use `copy` with `content` and `force: no` if you only want to create the file when it doesn't exist.

## Editing Existing Files

### lineinfile — Single Line Changes

The `lineinfile` module ensures a specific line exists (or doesn't) in a file. It's the most common module for small configuration edits.

#### Ensure a Line Is Present

```yaml
- name: Enable IP forwarding in sysctl
  lineinfile:
    path: /etc/sysctl.conf
    regexp: '^#?net\.ipv4\.ip_forward'
    line: 'net.ipv4.ip_forward = 1'

- name: Set timezone in PHP
  lineinfile:
    path: /etc/php/8.1/cli/php.ini
    regexp: '^;?date\.timezone'
    line: 'date.timezone = UTC'
```

The `regexp` matches the line to replace. If found, it's replaced with `line`. If not found, `line` is appended to the end of the file.

#### Insert After/Before a Specific Line

```yaml
- name: Add nameserver after the search line
  lineinfile:
    path: /etc/resolv.conf
    insertafter: '^search'
    line: 'nameserver 10.0.0.2'

- name: Add a setting before the closing bracket
  lineinfile:
    path: /etc/myapp/config.json
    insertbefore: '^\}'
    line: '  "debug": true,'
```

#### Remove a Line

```yaml
- name: Remove a deprecated option
  lineinfile:
    path: /etc/ssh/sshd_config
    regexp: '^UsePrivilegeSeparation'
    state: absent
  notify: restart sshd
```

#### Add to User's .bash_profile

```yaml
- name: Add custom PATH to deploy user's profile
  lineinfile:
    path: /home/deploy/.bash_profile
    line: 'export PATH="$HOME/.local/bin:$PATH"'
    create: yes
    owner: deploy
    group: deploy
    mode: '0644'
```

The `create: yes` option creates the file if it doesn't exist.

#### Multiple Lines with a Loop

```yaml
- name: Add environment variables to .bashrc
  lineinfile:
    path: /home/deploy/.bashrc
    line: "{{ item }}"
    create: yes
    owner: deploy
    group: deploy
  loop:
    - 'export EDITOR=vim'
    - 'export HISTSIZE=10000'
    - 'export HISTTIMEFORMAT="%F %T "'
    - 'alias ll="ls -la"'
```

### blockinfile — Multi-Line Sections

The `blockinfile` module manages a marked block of text within a file. It wraps content with begin/end markers so Ansible can find and update it on future runs.

#### Add a Block to a Config File

```yaml
- name: Add custom SSH banner config
  blockinfile:
    path: /etc/ssh/sshd_config
    marker: "# {mark} ANSIBLE MANAGED - custom settings"
    block: |
      Banner /etc/issue.net
      MaxAuthTries 3
      PermitRootLogin no
      PasswordAuthentication no
  notify: restart sshd
```

This produces:

```
# BEGIN ANSIBLE MANAGED - custom settings
Banner /etc/issue.net
MaxAuthTries 3
PermitRootLogin no
PasswordAuthentication no
# END ANSIBLE MANAGED - custom settings
```

#### Add Entries to /etc/hosts

```yaml
- name: Add application hosts
  blockinfile:
    path: /etc/hosts
    marker: "# {mark} ANSIBLE MANAGED - app cluster"
    block: |
      10.0.1.10 app-server-1
      10.0.1.11 app-server-2
      10.0.1.12 app-server-3
      10.0.1.20 db-primary
      10.0.1.21 db-replica
```

#### Insert After a Specific Line

```yaml
- name: Add iptables rules after the header
  blockinfile:
    path: /etc/sysconfig/iptables
    insertafter: '^:OUTPUT ACCEPT'
    marker: "# {mark} ANSIBLE MANAGED - app rules"
    block: |
      -A INPUT -p tcp --dport 80 -j ACCEPT
      -A INPUT -p tcp --dport 443 -j ACCEPT
      -A INPUT -p tcp --dport 8080 -s 10.0.0.0/8 -j ACCEPT
```

#### Remove a Block

```yaml
- name: Remove the managed block
  blockinfile:
    path: /etc/hosts
    marker: "# {mark} ANSIBLE MANAGED - app cluster"
    state: absent
```

### replace — Regex Search and Replace

The `replace` module does regex-based substitution across an entire file — similar to `sed`. Use it when you need to change multiple occurrences or patterns that `lineinfile` can't handle cleanly.

```yaml
- name: Comment out all DebugLevel lines
  replace:
    path: /etc/myapp/config.ini
    regexp: '^(DebugLevel\s*=.*)'
    replace: '# \1'

- name: Change listen address from localhost to all interfaces
  replace:
    path: /etc/redis/redis.conf
    regexp: '^bind 127\.0\.0\.1'
    replace: 'bind 0.0.0.0'
  notify: restart redis

- name: Update version string across the file
  replace:
    path: /opt/myapp/version.txt
    regexp: 'v1\.2\.3'
    replace: 'v1.3.0'
```

#### Restrict to a Section of the File

```yaml
- name: Change setting only within [database] section
  replace:
    path: /etc/myapp/config.ini
    after: '^\[database\]'
    before: '^\[.*\]'
    regexp: '^host\s*=.*'
    replace: 'host = db-new.internal'
```

## Deploying Scripts

### Simple Script Deployment

```yaml
- name: Deploy and register a maintenance script
  copy:
    src: scripts/maintenance.sh
    dest: /usr/local/bin/maintenance.sh
    owner: root
    group: root
    mode: '0755'
```

### Script with a Cron Job

```yaml
- name: Deploy cleanup script
  copy:
    src: scripts/cleanup-logs.sh
    dest: /usr/local/bin/cleanup-logs.sh
    owner: root
    group: root
    mode: '0755'

- name: Schedule cleanup script
  cron:
    name: "Daily log cleanup"
    hour: "2"
    minute: "30"
    job: "/usr/local/bin/cleanup-logs.sh >> /var/log/cleanup.log 2>&1"
    user: root
```

### Script with a systemd Service

```yaml
- name: Deploy application script
  copy:
    src: scripts/myapp-worker.sh
    dest: /usr/local/bin/myapp-worker.sh
    owner: root
    group: root
    mode: '0755'

- name: Deploy systemd service unit
  copy:
    content: |
      [Unit]
      Description=MyApp Worker
      After=network.target

      [Service]
      Type=simple
      ExecStart=/usr/local/bin/myapp-worker.sh
      Restart=always
      RestartSec=5
      User=appuser

      [Install]
      WantedBy=multi-user.target
    dest: /etc/systemd/system/myapp-worker.service
    owner: root
    group: root
    mode: '0644'
  notify:
    - reload systemd
    - restart myapp-worker
```

### Templated Script (Dynamic Content)

When a script needs host-specific variables:

```yaml
- name: Deploy monitoring script with host-specific values
  template:
    src: scripts/health-check.sh.j2
    dest: /usr/local/bin/health-check.sh
    owner: root
    group: root
    mode: '0755'
```

**templates/scripts/health-check.sh.j2:**

```bash
#!/bin/bash
# Deployed by Ansible — do not edit manually
set -euo pipefail

ENDPOINTS=(
{% for endpoint in health_check_endpoints %}
  "{{ endpoint }}"
{% endfor %}
)

ALERT_URL="{{ alert_webhook_url }}"

for url in "${ENDPOINTS[@]}"; do
  status=$(curl -s -o /dev/null -w "%{http_code}" "$url" || true)
  if [[ "$status" != "200" ]]; then
    curl -s -X POST "$ALERT_URL" \
      -H "Content-Type: application/json" \
      -d "{\"host\": \"{{ ansible_hostname }}\", \"url\": \"$url\", \"status\": \"$status\"}"
  fi
done
```

## Ad-Hoc File Operations

For quick one-off edits without writing a playbook:

```bash
# Copy a file to all web servers
ansible webservers -m copy -a "src=hotfix.conf dest=/etc/myapp/hotfix.conf owner=root mode=0644" -b

# Add a line to a config
ansible webservers -m lineinfile -a "path=/etc/sysctl.conf line='vm.swappiness = 10'" -b

# Create a directory
ansible all -m file -a "path=/opt/backups state=directory owner=root mode=0755" -b

# Replace a value in a config
ansible dbservers -m replace -a "path=/etc/redis/redis.conf regexp='^maxmemory .*' replace='maxmemory 2gb'" -b
```

## copy vs template: When to Use Which

| Scenario | Module | Reason |
|----------|--------|--------|
| Static config file | `copy` (with `src`) | No variables needed |
| Inline content, no variables | `copy` (with `content`) | Simple, no template file to maintain |
| File with host-specific values | `template` | Uses Jinja2 variables and facts |
| File with conditional sections | `template` | Jinja2 `{% if %}` blocks |
| File with loops | `template` | Jinja2 `{% for %}` blocks |
| Binary file (cert, compiled) | `copy` | Templates corrupt binary content |

## Backup Before Editing

All file-editing modules support `backup: yes` to create a timestamped copy before making changes:

```yaml
- name: Edit sshd_config (with backup)
  lineinfile:
    path: /etc/ssh/sshd_config
    regexp: '^#?PermitRootLogin'
    line: 'PermitRootLogin no'
    backup: yes
  notify: restart sshd
```

The backup is saved as `/etc/ssh/sshd_config.<timestamp>` on the remote host.

## Common Patterns

### Create a File Only If It Doesn't Exist

```yaml
- name: Create default config (don't overwrite if exists)
  copy:
    content: |
      [defaults]
      timeout = 30
      retries = 3
    dest: /etc/myapp/config.ini
    force: no
    owner: appuser
    group: appuser
    mode: '0644'
```

`force: no` skips the copy if the destination already exists.

### Atomic Multi-File Deployment

```yaml
- name: Deploy all config files from a directory
  copy:
    src: configs/myapp/
    dest: /etc/myapp/
    owner: root
    group: root
    mode: '0644'
    directory_mode: '0755'
  notify: restart myapp
```

When `src` ends with `/`, the **contents** of the directory are copied (not the directory itself).

### assemble — Build Config from Fragments

```yaml
- name: Deploy fragment for this app
  copy:
    content: |
      upstream {{ app_name }} {
          server {{ app_host }}:{{ app_port }};
      }
    dest: /etc/nginx/conf.d/upstreams.d/{{ app_name }}.conf

- name: Assemble all upstream fragments into one file
  assemble:
    src: /etc/nginx/conf.d/upstreams.d/
    dest: /etc/nginx/conf.d/upstreams.conf
  notify: reload nginx
```

### Ensure a Line in Multiple Files

```yaml
- name: Disable core dumps in all limit.conf files
  lineinfile:
    path: "{{ item }}"
    regexp: '^\*.*core'
    line: '*    hard    core    0'
  loop:
    - /etc/security/limits.conf
    - /etc/security/limits.d/90-custom.conf
```

## Tips and Gotchas

- **Idempotency** — `copy`, `template`, `lineinfile`, `blockinfile`, and `replace` are all idempotent. Running them twice produces the same result with no unnecessary changes.
- **Handlers** — Always use `notify` to trigger service restarts only when a file actually changes. Avoid unconditional restarts.
- **Mode quoting** — Quote file modes as strings: `mode: '0644'`. Unquoted YAML interprets octal numbers incorrectly.
- **Validation** — Use `validate` on critical system files (`sudoers`, `sshd_config`, `fstab`) to prevent deploying broken configs that could lock you out.
- **Diff mode** — Run with `--diff` to see exactly what changed: `ansible-playbook site.yml --diff`.
- **Check mode** — Always test file changes with `--check --diff` first in production.
- **line vs regexp in lineinfile** — `regexp` finds the line to replace; `line` is the replacement. Without `regexp`, Ansible just checks if `line` exists anywhere in the file.
- **blockinfile markers** — Customize markers to avoid conflicts when multiple roles manage the same file. Default markers are `# BEGIN ANSIBLE MANAGED BLOCK` / `# END ANSIBLE MANAGED BLOCK`.
- **Template newlines** — Add `\n` at the end of templates, or Jinja2 may strip the final newline. Use `#jinja2: keep_trailing_newline:True` in the template header if needed.
