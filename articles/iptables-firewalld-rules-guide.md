# Adding and Editing Firewall Rules: iptables and FirewallD

Different methods to add, modify, and persist firewall rules on Linux — covering iptables directly, iptables-save/restore, FirewallD commands, and direct XML editing.

## Method Overview

| Method | Tool | Persistence | Best For |
|--------|------|:-----------:|----------|
| iptables CLI | `iptables` | No (lost on reboot) | Quick testing, scripting |
| iptables-save/restore | `iptables-save`, `iptables-restore` | With service/file | Bulk edits, backups, migration |
| iptables service (RHEL 7) | `systemctl` + `/etc/sysconfig/iptables` | Yes | Legacy RHEL systems |
| firewall-cmd | `firewall-cmd --permanent` | Yes (after reload) | Modern RHEL/CentOS/Fedora |
| FirewallD XML files | Edit files in `/etc/firewalld/` | Yes (after reload) | Automation, templates |
| nftables | `nft` | With service/file | RHEL 9+, replacement for iptables |

## Method 1: iptables CLI (Runtime Only)

Rules added with `iptables` are immediate but lost on reboot.

### Add Rules

```bash
# Allow incoming SSH
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Allow incoming HTTP and HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Allow from specific IP
iptables -A INPUT -s 192.168.1.100 -j ACCEPT

# Allow from subnet
iptables -A INPUT -s 10.0.0.0/24 -p tcp --dport 3306 -j ACCEPT

# Allow established connections
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Allow loopback
iptables -A INPUT -i lo -j ACCEPT

# Drop all other incoming
iptables -A INPUT -j DROP

# Allow outgoing
iptables -A OUTPUT -j ACCEPT
```

### Insert Rules (At Specific Position)

```bash
# Insert at position 1 (top priority)
iptables -I INPUT 1 -p tcp --dport 22 -j ACCEPT

# Insert at position 3
iptables -I INPUT 3 -s 192.168.1.0/24 -j ACCEPT
```

### Delete Rules

```bash
# Delete by specification
iptables -D INPUT -p tcp --dport 80 -j ACCEPT

# Delete by line number
iptables -L INPUT --line-numbers
iptables -D INPUT 3

# Flush all rules in a chain
iptables -F INPUT

# Flush all chains
iptables -F

# Delete all user-defined chains
iptables -X
```

### View Rules

```bash
# List all rules
iptables -L -n -v

# List with line numbers (useful for insert/delete by position)
iptables -nvL --line-numbers

# List specific chain
iptables -L INPUT -n -v

# Show rules as commands (for scripting)
iptables -S

# Show rules for specific chain
iptables -S INPUT
```

### Advanced Rules

```bash
# Limit SSH connections per IP (max 5 concurrent)
iptables -A INPUT -p tcp --syn --dport 22 -m connlimit --connlimit-above 5 -j REJECT

# Rate limit (max 10 connections per minute)
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -m limit --limit 10/min --limit-burst 5 -j ACCEPT

# NAT (SNAT — static source NAT)
iptables -t nat -A POSTROUTING -s 192.168.0.0/24 -o eth0 -j SNAT --to-source 78.34.234.4

# NAT (MASQUERADE — dynamic source NAT)
iptables -t nat -A POSTROUTING -s 192.168.0.0/24 -o eth0 -j MASQUERADE

# DNAT (port forwarding to internal host)
iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 80 -j DNAT --to-destination 192.168.1.23:8080
```

### iptables-config Options

```bash
# /etc/sysconfig/iptables-config

# Auto-save rules on service stop/restart
IPTABLES_SAVE_ON_STOP="yes"
IPTABLES_SAVE_ON_RESTART="yes"

# Set to "no" if you manage rules manually and don't want
# service restarts to overwrite your saved rules file
```

## Method 2: iptables-save / iptables-restore

Best for bulk edits, backups, and deploying rules from files.

### Export Current Rules

```bash
# Save to file
iptables-save > /tmp/iptables-rules.txt

# Save with packet/byte counters
iptables-save -c > /tmp/iptables-rules-counters.txt

# View current rules in save format
iptables-save
```

### Edit Rules File

```bash
# Export
iptables-save > /tmp/rules.txt

# Edit with any text editor
vi /tmp/rules.txt
```

Example file format:

```bash
# Generated by iptables-save
*filter
:INPUT ACCEPT [0:0]
:FORWARD ACCEPT [0:0]
:OUTPUT ACCEPT [0:0]
-A INPUT -i lo -j ACCEPT
-A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT
-A INPUT -p tcp -m tcp --dport 22 -j ACCEPT
-A INPUT -p tcp -m tcp --dport 80 -j ACCEPT
-A INPUT -p tcp -m tcp --dport 443 -j ACCEPT
-A INPUT -j DROP
COMMIT
```

### Restore Rules from File

```bash
# Restore (replaces ALL current rules)
iptables-restore < /tmp/rules.txt

# Restore without flushing existing rules
iptables-restore -n < /tmp/rules.txt

# Test restore (check syntax without applying)
iptables-restore --test < /tmp/rules.txt
```

### Make iptables-save Persistent

```bash
# RHEL/CentOS 6 (iptables service)
service iptables save
# Saves to /etc/sysconfig/iptables

# RHEL/CentOS 7+ (with iptables-services package)
sudo dnf install -y iptables-services
sudo systemctl enable iptables
iptables-save > /etc/sysconfig/iptables

# Ubuntu/Debian (with iptables-persistent)
sudo apt install -y iptables-persistent
# Saves automatically during install, or:
sudo netfilter-persistent save
# Saves to /etc/iptables/rules.v4 and rules.v6

# Manual persistence via rc.local or systemd
echo 'iptables-restore < /etc/iptables.rules' >> /etc/rc.local
```

## Method 3: iptables Service (RHEL/CentOS)

```bash
# Install iptables service (not installed by default on RHEL 7+)
sudo dnf install -y iptables-services

# Disable firewalld (can't run both)
sudo systemctl stop firewalld
sudo systemctl disable firewalld
sudo systemctl mask firewalld

# Enable iptables service
sudo systemctl enable --now iptables

# Add rules normally
iptables -A INPUT -p tcp --dport 80 -j ACCEPT

# Save current rules to /etc/sysconfig/iptables
service iptables save
# or
iptables-save > /etc/sysconfig/iptables

# Restart service (reloads from /etc/sysconfig/iptables)
sudo systemctl restart iptables

# Edit the rules file directly
sudo vi /etc/sysconfig/iptables
sudo systemctl restart iptables
```

## Method 4: firewall-cmd (FirewallD)

The modern approach on RHEL 7+, CentOS 7+, Fedora.

### Runtime vs Permanent

```bash
# Runtime only (immediate, lost on reboot)
sudo firewall-cmd --add-port=8080/tcp

# Permanent (requires reload)
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --reload

# Add to both simultaneously
sudo firewall-cmd --add-port=8080/tcp
sudo firewall-cmd --permanent --add-port=8080/tcp

# Convert all runtime rules to permanent
sudo firewall-cmd --runtime-to-permanent
```

### Add Rules

```bash
# By service
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https

# By port
sudo firewall-cmd --permanent --add-port=8080/tcp
sudo firewall-cmd --permanent --add-port=5000-5100/tcp

# Rich rules (fine-grained control)
sudo firewall-cmd --permanent --add-rich-rule='rule family="ipv4" source address="192.168.1.0/24" port port="3306" protocol="tcp" accept'

# Port forwarding
sudo firewall-cmd --permanent --add-forward-port=port=80:proto=tcp:toport=8080

# Reload to apply permanent rules
sudo firewall-cmd --reload
```

### Remove Rules

```bash
sudo firewall-cmd --permanent --remove-service=http
sudo firewall-cmd --permanent --remove-port=8080/tcp
sudo firewall-cmd --permanent --remove-rich-rule='rule family="ipv4" source address="192.168.1.0/24" port port="3306" protocol="tcp" accept'
sudo firewall-cmd --reload
```

### View Rules

```bash
sudo firewall-cmd --list-all
sudo firewall-cmd --list-services
sudo firewall-cmd --list-ports
sudo firewall-cmd --list-rich-rules
```

## Method 5: FirewallD XML Files

Directly edit zone and service XML files for automation or templating.

### Zone Files

```bash
# Custom zones go here (override defaults)
ls /etc/firewalld/zones/

# Default zones (don't edit these directly)
ls /usr/lib/firewalld/zones/

# Copy and customize a zone
sudo cp /usr/lib/firewalld/zones/public.xml /etc/firewalld/zones/public.xml
sudo vi /etc/firewalld/zones/public.xml
```

Example zone file (`/etc/firewalld/zones/public.xml`):

```xml
<?xml version="1.0" encoding="utf-8"?>
<zone>
  <short>Public</short>
  <description>Public zone with custom rules</description>
  <service name="ssh"/>
  <service name="http"/>
  <service name="https"/>
  <port protocol="tcp" port="8080"/>
  <port protocol="tcp" port="8443"/>
  <rule family="ipv4">
    <source address="10.0.0.0/24"/>
    <port protocol="tcp" port="3306"/>
    <accept/>
  </rule>
</zone>
```

### Custom Service Files

```bash
# Create a custom service
sudo vi /etc/firewalld/services/myapp.xml
```

```xml
<?xml version="1.0" encoding="utf-8"?>
<service>
  <short>MyApp</short>
  <description>My Custom Application</description>
  <port protocol="tcp" port="8080"/>
  <port protocol="tcp" port="8443"/>
</service>
```

```bash
# Reload to pick up new files
sudo firewall-cmd --reload

# Use the custom service
sudo firewall-cmd --permanent --add-service=myapp
sudo firewall-cmd --reload
```

### Reload After XML Edits

```bash
# Always reload after editing XML files
sudo firewall-cmd --reload

# Or restart the service
sudo systemctl restart firewalld
```

## Method 6: nftables (RHEL 9+)

nftables replaces iptables as the backend. On RHEL 9+, `iptables` commands are translated to nftables internally.

### Direct nft Commands

```bash
# List current ruleset
sudo nft list ruleset

# Add a table
sudo nft add table inet filter

# Add a chain
sudo nft add chain inet filter input { type filter hook input priority 0 \; }

# Add rules
sudo nft add rule inet filter input tcp dport 22 accept
sudo nft add rule inet filter input tcp dport {80, 443} accept
sudo nft add rule inet filter input ip saddr 192.168.1.0/24 accept
sudo nft add rule inet filter input drop

# Delete a rule (by handle)
sudo nft -a list ruleset    # Shows handles
sudo nft delete rule inet filter input handle 5

# Flush a chain
sudo nft flush chain inet filter input

# Flush entire ruleset
sudo nft flush ruleset
```

### Persist nftables Rules

```bash
# Save to file
sudo nft list ruleset > /etc/nftables.conf

# Load from file
sudo nft -f /etc/nftables.conf

# Enable nftables service (loads /etc/nftables.conf on boot)
sudo systemctl enable --now nftables
```

### nftables Rule File Format

```bash
#!/usr/sbin/nft -f
# /etc/nftables.conf

flush ruleset

table inet filter {
    chain input {
        type filter hook input priority 0; policy drop;

        # Allow loopback
        iif lo accept

        # Allow established
        ct state established,related accept

        # Allow SSH
        tcp dport 22 accept

        # Allow HTTP/HTTPS
        tcp dport { 80, 443 } accept

        # Allow from subnet
        ip saddr 10.0.0.0/24 tcp dport 3306 accept

        # Log and drop everything else
        log prefix "nftables drop: " drop
    }

    chain output {
        type filter hook output priority 0; policy accept;
    }

    chain forward {
        type filter hook forward priority 0; policy drop;
    }
}
```

## Comparison: When to Use Which

| Scenario | Recommended Method |
|----------|-------------------|
| Quick test (temporary rule) | `iptables` CLI or `firewall-cmd` (no `--permanent`) |
| RHEL 7/8/9 production | `firewall-cmd --permanent` + `--reload` |
| Bulk rule deployment | `iptables-restore` from file or FirewallD XML |
| Legacy RHEL 6 | `iptables` + `service iptables save` |
| Automation (Ansible/Terraform) | FirewallD XML files or `firewall-cmd` |
| Ubuntu/Debian | UFW or `iptables-persistent` |
| Maximum performance | nftables (native, no translation layer) |
| Migration from iptables | `iptables-translate` to convert rules to nft |

## Translating iptables to nftables

```bash
# Translate a single iptables rule to nftables
iptables-translate -A INPUT -p tcp --dport 22 -j ACCEPT
# Output: nft add rule ip filter INPUT tcp dport 22 counter accept

# Translate an entire ruleset
iptables-save | iptables-restore-translate

# Translate ip6tables
ip6tables-translate -A INPUT -p tcp --dport 80 -j ACCEPT
```

## Scripting Firewall Rules

### Bash Script (iptables)

```bash
#!/bin/bash
# firewall-setup.sh

# Flush existing rules
iptables -F
iptables -X

# Default policies
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# Allow loopback
iptables -A INPUT -i lo -j ACCEPT

# Allow established
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Allow SSH
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# Allow HTTP/HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Save rules
iptables-save > /etc/sysconfig/iptables
echo "Firewall rules applied and saved."
```

### Bash Script (FirewallD)

```bash
#!/bin/bash
# firewalld-setup.sh

SERVICES="ssh http https"
PORTS="8080/tcp 8443/tcp"
TRUSTED_SUBNET="10.0.0.0/24"

# Add services
for svc in $SERVICES; do
    firewall-cmd --permanent --add-service="$svc"
done

# Add ports
for port in $PORTS; do
    firewall-cmd --permanent --add-port="$port"
done

# Add trusted subnet for MySQL
firewall-cmd --permanent --add-rich-rule="rule family=ipv4 source address=${TRUSTED_SUBNET} port port=3306 protocol=tcp accept"

# Reload
firewall-cmd --reload

echo "FirewallD rules applied."
firewall-cmd --list-all
```

## Troubleshooting

### Check Which Firewall Is Active

```bash
# Check if firewalld is running
systemctl is-active firewalld

# Check if iptables service is running
systemctl is-active iptables

# Check if nftables is running
systemctl is-active nftables

# See actual kernel rules regardless of frontend
iptables -L -n -v
# or
nft list ruleset
```

### Rules Not Taking Effect

```bash
# FirewallD: did you reload?
sudo firewall-cmd --reload

# iptables: check rule order (first match wins)
iptables -L INPUT --line-numbers -n

# Check if rule is in the right chain
# INPUT = incoming to this host
# OUTPUT = outgoing from this host
# FORWARD = passing through (routing)

# Check default policy
iptables -L | grep "Chain.*policy"
```

### Lock Yourself Out (Recovery)

```bash
# If you can't SSH in:
# 1. Access via console (physical/IPMI/cloud console)
# 2. Flush all rules:
iptables -F
iptables -P INPUT ACCEPT

# Or for firewalld:
systemctl stop firewalld

# Or boot into single-user/rescue mode
```

## Quick Reference

| Action | iptables | firewall-cmd |
|--------|----------|-------------|
| Allow port | `iptables -A INPUT -p tcp --dport 80 -j ACCEPT` | `firewall-cmd --permanent --add-port=80/tcp` |
| Allow service | N/A (use port) | `firewall-cmd --permanent --add-service=http` |
| Block IP | `iptables -A INPUT -s 1.2.3.4 -j DROP` | `firewall-cmd --permanent --add-rich-rule='rule family=ipv4 source address=1.2.3.4 drop'` |
| List rules | `iptables -L -n` | `firewall-cmd --list-all` |
| Save rules | `iptables-save > /etc/sysconfig/iptables` | `firewall-cmd --runtime-to-permanent` |
| Delete rule | `iptables -D INPUT 3` | `firewall-cmd --permanent --remove-port=80/tcp` |
| Flush all | `iptables -F` | `firewall-cmd --reload` (reloads from permanent) |
| Persist | `service iptables save` | `--permanent` flag |
